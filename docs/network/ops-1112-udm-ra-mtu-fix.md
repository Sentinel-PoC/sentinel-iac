# OPS-1112: UCG Fiber RA MTU Fix — br0 LAN Advertises 1500

## Problem

The UCG Fiber (208-Ck2-001, 192.168.12.1) was advertising MTU 9216 in IPv6 Router
Advertisements for the Default LAN (192.168.12.0/24, prefix 2001:1960:2802:6546::/64).

Root cause: `global_switch.jumboframe_enabled = True` in UniFi Network config causes
all bridge interfaces (br0, br50, br100, br200) to have kernel MTU 9216. The dnsmasq
`enable-ra` option reads the interface MTU and advertises it in RA packets. VM NICs
(eth0) are 1500 MTU, causing a "MTU blackhole" for IPv6 TCP segments >= 4274 bytes.

iac-control (.210) confirmed before fix:
```
2001:1960:2802:6546::/64 proto ra metric 512 expires 85843sec mtu 9216 hoplimit 64 pref high
default via fe80::1e0b:8bff:fe18:14b5 proto ra metric 512 expires 1540sec mtu 9216 hoplimit 64 pref high
```

## Investigation

- RA source: UCG Fiber (192.168.12.1), NOT radvd on any PVE host
- No radvd found on pve (.6), 208-pve2 (.56), pve3 (.57), pve4 (.60)
- RA sent by dnsmasq (managed by ubios-udapi-server) with `enable-ra` and
  `ra-param=br0,high,600,1800` — no explicit MTU override, inherits br0 kernel MTU
- br0 kernel MTU: 9216 (set by ubios-udapi-server due to `jumboframe_enabled: True`)
- UniFi Network API field `ra_link_mtu` is NOT recognized by firmware v5.1.15 / 
  Network v10.4.57 — API silently drops it; MongoDB write confirmed it's not translated
  by the Java app into the udapi config

## Fix Applied (2026-06-01)

**Not IaC-managed** — the UCG Fiber network config is managed internally by
ubios-udapi-server; sentinel-iac has no Ansible role covering this.

### Step 1: dnsmasq ra-param MTU override

Modified `/run/dnsmasq.dhcp.conf.d/dhcp.dhcpServers-net_Default_br0_192-168-12-0-24_IPV6.conf`
to add `mtu:1500` to the `ra-param` directive:

```
ra-param=br0,mtu:1500,high,600,1800
```

Verified via tcpdump on br0:
```
mtu option (5), length 8 (1):  1500
```

### Step 2: Persistent fix via systemd path watcher

Since `/run/dnsmasq.dhcp.conf.d/` is regenerated by ubios-udapi-server on every
config change, created:

- `/data/scripts/fix-ra-mtu-1500.sh` — script that patches ra-param and restarts dnsmasq
- `/etc/systemd/system/fix-ra-mtu.path` — watches the dnsmasq conf file for changes
- `/etc/systemd/system/fix-ra-mtu.service` — runs the fix script when path changes
- `/etc/systemd/system/fix-ra-mtu-boot.service` — runs at boot after udapi-server starts

Both path and boot services are enabled:
```
systemctl enable fix-ra-mtu.path fix-ra-mtu-boot.service
```

### Step 3: MongoDB ra_link_mtu (informational)

Added `ra_link_mtu: 1500` to the Default network document in MongoDB (port 27117):
```javascript
db.networkconf.update({name: "Default"}, {$set: {ra_link_mtu: 1500}})
```
This is informational — the current firmware does not translate this field.
When Ubiquiti adds support for `ra_link_mtu` in a future firmware update, this
field will already be set and the systemd workaround can be removed.

## Verification

After fix (iac-control 192.168.12.210):
```
2001:1960:2802:6546::/64 proto ra metric 512 expires 86270sec mtu 1500 hoplimit 64 pref high
default via fe80::1e0b:8bff:fe18:14b5 proto ra metric 512 expires 1731sec mtu 1500 hoplimit 64 pref high
```

Large IPv6 ICMP (4274, 5000, 8000 bytes) between .12 hosts: 0% packet loss.
Large IPv6 TCP (5000 byte send to port 22): success.

## Known Limitations

1. **Firmware update risk**: A UCG Fiber firmware update may overwrite `/etc/systemd/system/`
   unit files or change the dnsmasq conf path. If the RA reverts to 9216 after a firmware
   update, re-run `/data/scripts/fix-ra-mtu-1500.sh` manually and re-enable the units.

2. **Personal VLAN (br50)** also has `ra_link_mtu` not set and potentially advertises 9216.
   Clients on that VLAN (192.168.50.x) may have the same issue. Separate fix needed.

3. **Preferred fix**: Disable `jumboframe_enabled` selectively OR wait for Ubiquiti to
   expose `ra_link_mtu` in their Network API. Tracked: see follow-up issue.
